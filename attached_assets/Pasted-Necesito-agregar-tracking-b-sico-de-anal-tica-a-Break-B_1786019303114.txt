Necesito agregar tracking básico de analítica a Break Buddy, para poder ver: visitas únicas por IP, si una IP volvió a entrar más de una vez, cuánto tiempo se quedó cada sesión en la app, y detectar "rebotes" (entró y se fue en menos de 2 segundos). Esto es para revisión interna nuestra, no un dashboard público.

Si algo de esto no queda claro o hay una decisión de diseño que no cubrí, preguntame antes de improvisar. No repitas un mismo chequeo en loop sin cambiar nada.

PARTE 1 — Backend: tabla y endpoint para capturar eventos

1. Agregá una tabla nueva en lib/db/src/schema (seguí el mismo estilo que las tablas existentes) llamada analyticsSessions, con estas columnas:
   - id (uuid, primary key)
   - sessionId (string, generado por el cliente, identifica una pestaña/sesión de navegación)
   - ipHash (string) — el hash SHA-256 de la IP del visitante, NUNCA guardes la IP en texto plano, es un dato sensible y no lo necesitamos crudo para esto
   - userAgent (string, opcional)
   - firstSeenAt (timestamp)
   - lastSeenAt (timestamp) — se va actualizando con cada heartbeat, para poder calcular la duración de la sesión como lastSeenAt - firstSeenAt
   - pingCount (integer, default 0) — cuántos heartbeats mandó esa sesión

Generá la migración correspondiente con Drizzle, igual que se hace hoy para el resto de las tablas.

2. Agregá un endpoint público (sin autenticación, pero con rate limit razonable tipo el que ya existe para otros endpoints públicos) POST /api/analytics/ping en artifacts/api-server/src, que reciba { sessionId } en el body y haga upsert sobre analyticsSessions:
   - Si sessionId no existe: crea la fila, con firstSeenAt = lastSeenAt = ahora, pingCount = 1, ipHash calculado del req (usá la misma lógica de IP real que ya usa el resto del proyecto para el rate limiting, considerando el proxy de Replit), userAgent del header.
   - Si sessionId ya existe: actualiza lastSeenAt = ahora, incrementa pingCount en 1.

3. Agregá un endpoint GET /api/analytics/summary, protegido por un header simple x-admin-key que tiene que matchear la variable de entorno ADMIN_ANALYTICS_KEY (si no matchea, devolvé 401). Este endpoint devuelve un JSON con:
   - totalSessions: cantidad total de filas en analyticsSessions
   - uniqueIpCount: cantidad de ipHash distintos
   - returningIpCount: cantidad de ipHash que aparecen en más de una sesión (mismo ipHash, distinto sessionId)
   - avgSessionDurationSeconds: promedio de (lastSeenAt - firstSeenAt) en segundos, sobre todas las sesiones
   - bounceCount: cantidad de sesiones donde pingCount es 1 Y (lastSeenAt - firstSeenAt) sea menor a 2 segundos, o donde pingCount sea 1 directamente (sesiones que nunca mandaron un segundo heartbeat)
   - sessionsPerDay: un array agrupando totalSessions por día (usando firstSeenAt), para poder ver la evolución día a día

No hace falta que armes ninguna pantalla/dashboard visual para esto — con que devuelva ese JSON alcanza, lo voy a revisar yo directamente.

PARTE 2 — Frontend: mandar los pings

En artifacts/break-buddy/src, agregá un módulo chico (ej. src/lib/analytics.ts) que:
1. Al montar la app (en App.tsx, una sola vez), genere o recupere un sessionId usando crypto.randomUUID(), guardado en sessionStorage (no localStorage, tiene que ser por pestaña, no persistir para siempre) bajo una clave tipo "bb-session-id".
2. Mande un POST a /api/analytics/ping apenas arranca la app.
3. Mande otro ping cada 20 segundos mientras la pestaña esté visible (usá document.visibilityState para pausarlo si la pestaña pasa a segundo plano, y reanudarlo cuando vuelve a estar visible).
4. Mandá un último ping al cerrar/salir de la pestaña usando navigator.sendBeacon (más confiable que fetch en el evento de unload), apuntando al mismo endpoint.

No hace falta trackear pantallas o pasos individuales dentro de la app (onboarding, break, etc.) — con esto alcanza para lo que necesito ahora: tiempo total en la app y recurrencia por IP.
